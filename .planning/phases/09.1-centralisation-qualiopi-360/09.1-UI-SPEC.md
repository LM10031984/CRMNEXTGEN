## Spacing Scale

Declared values (all multiples of 4 — Tailwind 3.4.17 defaults preserved since RESP-01 Phase 2 verdict):

| Token | px | Tailwind | Usage in Phase 9.1 |
|-------|----|---------|---------------------|
| xs | 4 | `gap-1`, `p-1` | Icon gaps inside DocStatusBadge / DocCellMenu items |
| sm | 8 | `gap-2`, `p-2`, `px-2`, `py-1.5` | Compact element spacing (matrix cell padding, filter chip gap) |
| md | 16 | `gap-4`, `p-4`, `space-y-4` | Default surface padding (mobile page padding) |
| lg | 24 | `gap-6`, `p-6`, `space-y-6` | Card padding desktop (PrioCard, MatrixCard wrapper) |
| xl | 32 | `gap-8`, `p-8`, `space-y-8` | Layout gaps (`p-4 md:p-8` page main) |
| 2xl | 48 | `gap-12` | Major section breaks (between "Documents session" block and "Documents participants" matrix) |
| 3xl | 64 | `space-y-16` | Timeline year jalon vertical rhythm (mobile compact: 32px, desktop: 64px) |

**Exceptions (documented, intentional):**
- **Matrix cell height:** `h-9` (36px) — needed to fit `<DocStatusBadge h-6 w-6>` + `<DocCellMenu>` trigger with `py-1.5` while keeping density acceptable for ~14 columns × 30 rows.
- **DocStatusBadge size:** `h-6 w-6` (24px) — tighter than spacing scale to fit dense matrix grid. Icon inside is `h-3 w-3` (12px).
- **Timeline dot:** `h-3 w-3` on the rail, with `12px` rail width — too small to be a spacing token but reproducible across the timeline.

## Typography

Inter + system fallback. **5 sizes + 4 weights — INHERITED from the existing QualiOF design system frozen pre-9.1.** Heights are line-heights, not paddings.

> **Explicit override of GSD typography ceiling (max 4 sizes / max 2 weights).**
> Phase 9.1 is an **insertion mid-milestone** into an already-shipped system. Phases 1–9 already use 5 active sizes (`text-xs` 12px, `text-sm` 14px, `text-base` 16px, `text-lg` 18px, `text-2xl` 24px) and 4 weights (`font-normal` 400, `font-medium` 500, `font-semibold` 600, `font-bold` 700) **everywhere**.
>
> **a11y validation already exists:** Phase 6 audit verdict `PASS_AVEC_NOTES` (`.planning/phases/06-dashboard-hierarchisation-et-a11y/06-VERIFICATION.md`) confirmed **all WCAG AA contrast checks pass** with Inter at these weights/sizes (7 Badge variants, PrioCard tokens, body text, navigation labels).
>
> **Verifiable shipped usage (per token):**
> - `text-xs` 12px — sidebar nav meta (Phase 2 `SidebarNav`), filter chip labels (Phase 9 leads), PrioCard sub-labels (Phase 6), footer `uploaded by` (Phase 5 Documents card)
> - `text-sm` 14px — body throughout (forms Phase 7, table rows fiche apprenant Phase 5, drawer body Phase 8)
> - `text-base` 16px — section headings dashboard (Phase 6 `CollapsibleSection`), card titles fiche session (Phase 5), modal body emphasis (Phase 4 `UserMenuButton` AlertDialog)
> - `text-lg` 18px — page heading drawer (Phase 4 notif panel), Dialog `Dialog.Title` (Phase 8 invitation), Breadcrumb terminal (Phase 5)
> - `text-2xl` 24px — PrioCard value (Phase 6 `app/app/page.tsx:382`), KPI display dashboard (Phase 6), trésorerie totals (Phase 3 `dossiers-opco`)
> - `font-normal` 400 — body throughout (every Phase)
> - `font-medium` 500 — Badge variants (Phase 8 `lib/badge-variants.ts`), emphasis labels (Phase 5 fiche apprenant), PrioCard meta uppercase (Phase 6)
> - `font-semibold` 600 — section headings (Phase 6 `CollapsibleSection`), Dialog titles (Phase 4/8), Breadcrumb current (Phase 5)
> - `font-bold` 700 — PrioCard values (Phase 6), KPI displays (Phase 3 trésorerie), dashboard headline numbers (Phase 6)
>
> **Rationale for opt-out:** Reducing to 4 sizes + 2 weights would force Phase 9.1 to introduce a parallel typographic system, creating **visual divergence with shipped UI** on fiche session, fiche apprenant, fiche produit — the three surfaces this phase modifies. Per CONTEXT.md D-Phase9-A through D-Phase9-N, Phase 9.1 explicitly inherits the existing token system. **Conservation du design system existant est plus important que conformité mécanique au plafond GSD pour une phase d'insertion mid-milestone.**
>
> **Scope of this override:** Limited to Phase 9.1. Does not authorize new sizes or weights beyond the 5+4 already shipped. Any *new* token would still need a separate justification.

| Role | Tailwind | px / weight / line-height | Usage in Phase 9.1 |
|------|----------|---------------------------|---------------------|
| Body | `text-sm` | 14 / 400 (default) / 1.5 | Matrix cell content, table rows, drawer body |
| Body emphasis | `text-sm font-medium` | 14 / 500 / 1.5 | Participant names, doc labels, CTA text |
| Label / meta | `text-xs` | 12 / 500 / 1.5 | Filter chip labels, footer "uploaded by", PrioCard sub |
| Heading section | `text-base font-semibold` | 16 / 600 / 1.3 | "Documents session" / "Documents participants" titles, year jalons "2026" |
| Heading page | `text-lg font-semibold` | 18 / 600 / 1.3 | Drawer titles ("Émargement détaillé"), Dialog `Dialog.Title` |
| Display KPI | `text-2xl font-bold tabular-nums` | 24 / 700 / 1.2 | PrioCard value (consistent with existing PrioCard in `app/app/page.tsx:382`) |

**Numeric values** always `tabular-nums` for alignment (PrioCard values, batch counts, hour totals).
**`uppercase tracking-wide text-xs text-muted-foreground font-medium`** reserved for PrioCard labels (existing convention).
**Truncation rule:** participant names and doc labels `truncate` past 28 chars on mobile, 40 chars on desktop. Full name available via `title` attribute (also serves accessibility — see a11y section).

## Color

Project palette is **already locked** by `tailwind.config.ts` and Phase 6 a11y audit (UX-13 verdict PASS_AVEC_NOTES, all 7 Badge variants WCAG AA). Phase 9.1 does **not** introduce new tokens.

| Role | Token | Hex / Tailwind | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `background` | `#FAFBFC` | Page background, drawer overlay base |
| Surface (30%) | `white` + `border` | `#FFFFFF` on `#E2E8F0` border | Cards (matrix, PrioCard, timeline session card, tab panel) |
| Accent (10%) | `primary` | `#00527A` (Start Academy bleu) | **Reserved-for list** below |
| Destructive | `red-*` (50/100/200/700) | Tailwind defaults | Delete actions, MISSING pastille, error toasts |

**Accent `primary` reserved for (explicit list — never "all interactive"):**
1. Primary CTA buttons (`bg-primary text-white` — e.g. "Re-générer les X sélectionnés", "Uploader signé")
2. Active tab indicator in `<ProductTabs>` (underline + `text-primary`)
3. Active filter chip (matrix filters: `bg-primary-50 text-primary-700 border-primary-100`)
4. Selected matrix row left-border (`border-l-4 border-primary` when checkbox cochée)
5. Breadcrumb hover state (`hover:text-primary`)
6. PrioCard "primary" variant background tint (`border-primary-200 bg-primary-50/50` — same as existing Phase 6 PrioCard)
7. Hover state on cross-navigation `<Link>` to other entities (text turns `text-primary` underline)

**Pastille palette — `<DocStatusBadge>` state → variant map (locked by D-06):**

| State | Variant | Background | Foreground | Icon | A11y label (`aria-label`) |
|-------|---------|-----------|------------|------|---------------------------|
| `MANUAL_OK` + uploadedPdf | success-solid | `bg-emerald-600` | `text-white` | `Check h-3 w-3` | "{label} : signé et uploadé" |
| `GENERATED` | success-soft | `bg-emerald-100 border-emerald-300` | `text-emerald-700` | `Check h-3 w-3` | "{label} : généré" |
| `MANUAL_OK` + `warning='no_proof'` | warning | `bg-amber-100 border-amber-300` | `text-amber-700` | `AlertTriangle h-3 w-3` | "{label} : marqué OK sans preuve uploadée" |
| `MISSING` | danger | `bg-red-100 border-red-300` | `text-red-700` | `X h-3 w-3` | "{label} : manquant" |
| `NA` (doc non applicable) | muted | `bg-slate-100` | `text-slate-400` | `Minus h-3 w-3` | "{label} : non applicable" |
| `RUNNING` (transient, BullMQ in flight) | info | `bg-sky-50 border-sky-200` | `text-sky-700` | `Loader2 h-3 w-3 animate-spin` | "{label} : génération en cours" |

**Color contrast verification (WCAG AA):** All 6 variants use Tailwind 50/100/300/600/700 combinations confirmed compliant by Phase 6 a11y audit (`.planning/phases/06-dashboard-hierarchisation-et-a11y/06-A11Y-AUDIT.md`). No new colors introduced.

**Anti-pattern (forbidden):**
- ❌ Random hex colors outside the project palette (use `text-emerald-700` not `text-[#15803D]`)
- ❌ Using `primary` for matrix cell pastilles (reserved for CTAs and selection state only)
- ❌ Mixing semantic colors (e.g. orange for both warning and primary action)

## Edge Cases

### Matrix
- **0 participants**: Empty state per copywriting. Filters and BatchBar hidden.
- **30+ participants**: Matrix renders all rows (no pagination — D-14 says 1-2 clics, pagination would be 3 clicks). Vertical scroll natural. Sticky header makes this acceptable.
- **Participant long name** (e.g. "Marie-Christine de la VALLÉE-PERRIN"): truncate at 28 chars mobile, 40 desktop, full name in `title` attribute (also reachable via screen reader as `aria-label` of the `<Link>`).
- **All docs MISSING** for a session: column counts shown in subtitle `0 / 14 documents suivis · 0 % complet`.
- **Cell PROGRAMME for participant with no productDoc** (rare — product never had a programme PDF generated): cell is `MISSING` (red), menu offers `Générer` (routes to `generateProductProgramme`, which produces a product-level doc consumed by all participants — Bug P0 resolution).
- **Cell AGEFICE for non-AGEFICE participant**: state `NA` (gray Minus). No menu. Tooltip `Non applicable — financement non AGEFICE`.
- **Émargement partial** (3/4 demi-journées signées): cell renders `MISSING` red, tooltip `3/4 demi-journées signées — cliquer pour le détail`, click opens `<AttendanceDetailDrawer>`. Per RESEARCH Pitfall 5.
- **Concurrent edit** (2 admins same participant): Server action uses `jsonb_set` raw query for atomic patch (RESEARCH Pitfall 2). UI does not handle conflict warning — last-write-wins. Audit log captures both writes.
- **Worker stub fallback** (Ollama down → stub content): cell border is `border-dashed border-amber-400`, tooltip `Contenu générique (Ollama HS) — à régénérer avant audit`. Reuses pattern from `ClosureBatchProgress`.
- **Doc generated but PDF link 404** (MinIO unavailable): cell still shows GENERATED state (DB says generated). Click → `/api/documents/{id}` returns 404 → existing error page. Toast not shown (browser handles). NOTE: this is degraded operation, not a 9.1 design concern.
- **Selection across filters**: changing filters while rows are selected → selected rows that disappear from filter remain in selection state. BatchBar shows `{N} apprenant(s) sélectionné(s) (dont {M} non visible(s) en raison des filtres)`.

### Timeline (fiche apprenant)
- **Participations spanning year boundary** (e.g. session 28/12/2025 → 03/01/2026): year is assigned by `startDate` (Dec 2025 here).
- **Same-day sessions**: stack within the same year jalon, ordered by `startDate` desc (existing convention).
- **Active session** (startDate ≤ today ≤ endDate): no special badge in 9.1 (deferred to Phase 10 alerts). Card renders normally.
- **Cancelled session** (status CANCELLED): renders in muted card `bg-muted/30 opacity-70` + chip `Badge variant=muted`+`Annulée`.
- **Participation with 0 docs tracked**: completeness chip shows `○○○○○ 0/N`.
- **Apprenant with 50+ sessions**: timeline scrolls naturally. No collapse needed at this scale. If > 100 → consider year-collapse (deferred V2).

### Product Tabs
- **Click on tab with no URL change** (already active): no-op (Next.js dedupes navigation).
- **URL `?tab=invalid`**: defaults to `stats` tab (Server Component coerces unknown values).
- **Programme tab with 0 PDF + 0 markdown**: see empty state.
- **Apprenants formés tab with apprenant who participated in 5 sessions of this product**: row shows the apprenant once with `5 sessions` chip.

### Dialog / Drawer
- **User closes dialog mid-upload**: `AbortController` cancels server action, no partial DB write (server action is atomic via Prisma transaction). Toast: silent (user explicitly cancelled).
- **Drawer with > 7 days attendance**: body scrolls vertically, header stays sticky.

## Open Questions (visual decisions deferred to planning)

These are not in CONTEXT.md and are this researcher's recommendations for the planner to lock or override.

1. **Exact pastille variant for `GENERATED` vs `MANUAL_OK + uploaded`** — recommendation: use **two shades of green** (light `bg-emerald-100 border-emerald-300` for GENERATED, solid `bg-emerald-600 text-white` for MANUAL_OK uploaded) to visually distinguish "generated but not yet validated" from "signed and uploaded". CONTEXT.md D-06 says "vert" for both — but the workflow distinction (D-01 "génération d'abord, signature ensuite") justifies a visual hierarchy.
2. **Maximum visible columns desktop matrix without horizontal scroll** — recommendation: design for 14 columns fitting at `xl` (1280px) with `min-w-[44px]` cells = 616px for cells + 280px for participant col = 896px content + 384px margins. Should fit comfortably on a 14" MacBook (1440px) without horiz scroll. AGEFICE conditional column = 15 max.
3. **Hover state on matrix cell** — recommendation: `hover:bg-muted/30` row-wide + cell `hover:ring-1 hover:ring-primary-200` for the focused cell. Subtle enough to not steal attention from the pastille.
4. **Selected row visual** — recommendation: `border-l-4 border-primary bg-primary-50/30` (left bar + tint). Alternative could be checkbox-only marker, but the left bar makes scanning selection state at distance trivial.
5. **Year jalon click behavior** — recommendation: **non-interactive** (decorative h3 + visual rail). D-08 wording "sessions = points cliquables" confirms only sessions are interactive, not year markers. Locked unless Laurent overrides.
6. **Tab transition animation** — recommendation: `transition-opacity duration-150` simple fade. Slide is heavier and not needed for content blocks. Per RESEARCH discretion zone.
7. **BatchBar exact placement on mobile** — recommendation: fixed bottom inset-0 full-width with `pb-safe` (iOS safe area). On desktop, pill `fixed bottom-4 left-1/2 -translate-x-1/2`. Both pass through opacity-0/100 with `slide-in-from-bottom-4`.
8. **AGEFICE column conditional visibility** — recommendation: **always visible** but cells `NA` for non-AGEFICE participants. Per RESEARCH Open Question 3 — keeps matrix shape rectangular and predictable for scan. Alternative (hide column if 0 AGEFICE participants) optimizes density at the cost of changing layout based on data.
9. **Satisfaction chaud vs froid = 1 or 2 columns?** — recommendation: **2 columns** (Sc / Sf), per RESEARCH Open Question 1. Two distinct Qualiopi docs (J+1 vs J+90) deserve distinct cells. CONTEXT.md D-04 listed "Satisfaction" generically; the matrix is finer-grained.
10. **Assiduité = upload-only (no generator)** — recommendation: lock per RESEARCH Open Question 2. Cell offers only `Téléverser signé` action. Phase 10 could add generation from Attendance aggregate.
