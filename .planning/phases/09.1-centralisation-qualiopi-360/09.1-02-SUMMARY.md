## Pitfalls mitigés (de RESEARCH.md)

### Pitfall 1 — Skip-existing bypass pour mode mono ✅

`forceMono = options.force === true && participantIds.length === 1` strictement.
Quand `forceMono === true` → `alreadyDoneByParticipant = new Map()` (vide) → la liste `kindsToProcess.filter(k => !done.has(k))` passe **tout**.
En mode global, force est ignoré (skip-existing reste actif, protection contre régen accidentelle).
**Test 3 + Test 4 single-participant.test.ts couvrent les 2 cas.**

### Pitfall 2 — Race condition `docStatus` Json patch ✅

`prisma.$executeRaw(Prisma.sql\`UPDATE "SessionParticipant" SET "docStatus" = jsonb_set(COALESCE(...), {docType}, entry, true)\`)` atomique côté Postgres.
**3 utilisations** : markDocStatus + uploadSignedDoc + deleteDocument (reset via opérateur `-`).
**Test 6 qualiopi-matrix.test.ts** : `executeRaw` toHaveBeenCalledTimes(1) sur uploadSignedDoc success.

### Pitfall 3 — Filtres matrice cross-tenant ✅

Defense-in-depth :
1. `findFirst` court-circuit avec `where: { id, session: { tenantId: user.tenantId } }` → retour 'Inscription introuvable' si cross-tenant.
2. Filtre raw SQL `WHERE id = ${pid}::uuid AND "sessionId" IN (SELECT id FROM "TrainingSession" WHERE "tenantId" = ${tenantId}::uuid)` → 0 rows updatées si bypass de niveau 1.
**Test 2 qualiopi-matrix.test.ts** couvre.

### Pitfall 4 — Composant client avec props non-sérialisables ✅

DocCellMenu accepte uniquement primitive props (strings + enum state). UploadSignedDocDialog idem. Pas de Date / Function / Prisma object passé en RSC boundary.
