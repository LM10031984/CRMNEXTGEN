<domain>
## Phase Boundary

**Délivrer la centralisation visuelle des documents Qualiopi par session/apprenant/produit**, en s'appuyant sur le modèle `SessionParticipant` × `Document` déjà en place. Le but : un auditeur Qualiopi doit retrouver tous les docs d'un stagiaire en 1-2 clics depuis la fiche session, et Laurent doit pouvoir générer/re-générer un doc ciblé sans wizard.

**Inclus dans cette phase :**
- Matrice visuelle stagiaire × document sur la fiche session (rendu PrioCard + pastilles colorées, pas grille Excel)
- Re-génération ciblée d'un doc pour 1 stagiaire (bouton ligne + sélection multi)
- Workflow upload du PDF signé après génération + warning si coché sans preuve
- Timeline fiche apprenant regroupée par année (drill-down sessions)
- Refonte fiche produit en 4 onglets (Stats / Sessions / Apprenants formés / Programme)
- Linking cross-entité Airtable-style (tout est cliquable et navigable)
- Résolution du Bug P0 « Programme dupliqué N fois » (structurelle : 1 PDF stocké, N statuts)

**Hors scope (= Phase 10) :**
- Scoring des 32 indicateurs Qualiopi officiels
- Notification cloche + email proactives 7j avant fin de session
- Rapport PDF audit blanc téléchargeable

**Hors scope (= Phase 11) :**
- Refonte module Factures (relances, NCN, export comptable)

</domain>

<decisions>
## Implementation Decisions

### Modélisation des statuts docs

- **D-01** : Le workflow standard est *« génération IA d'abord, signature/upload ensuite »*. La Convention (et les autres docs générables par l'app) est toujours produite par le closure-pack en premier (`status=GENERATED`). Quand l'admin coche « Convention signée » sur la matrice, l'app ouvre un upload pour le PDF signé scanné. Coché sans upload → warning visible ⚠️ « preuve manquante » mais autorisé (cas dérogatoire admis).
- **D-03** : Grain statuts = **3 états** :
  - `GENERATED` (PDF produit par l'app, pas encore validé)
  - `MANUAL_OK` (PDF signé uploadé OU validé manuellement par admin)
  - `MISSING` (rien fait)
- **D-07** : Pas de nouveau model BDD. La matrice est **dérivée** de `Document` existant + nouveau champ JSON `SessionParticipant.docStatus` (clé = DocType, valeur = state + uploadedSignedPdfUrl optionnel). Source unique de vérité : `Document` pour les PDF, `SessionParticipant.docStatus` pour les états manuels.

### Périmètre des documents (PDF stocké vs statut suivi)

- **D-04** : Liste figée des doc types. Tous les statuts sont par-participant (matrice 1 ligne par stagiaire). Le PDF physique peut être session-wide ou participant-wide :

| Doc | PDF stocké | Statut suivi |
|-----|-----------|-------------|
| Programme de formation | Session (1 fichier) | Participant (remis ?) |
| Convention de formation | Participant | Participant |
| **Convocation** | **Participant** | Participant |
| Pré-accord OPCO | Participant | Participant |
| Supports pédagogiques | Session (1 fichier promo) | Participant (remis ?) |
| **Émargement** | **Participant** | Participant (agrégé multi-jours) |
| Déroulé pédagogique | Session | Session-only |
| Certificat de réalisation | Participant | Participant |
| Attestation | Participant | Participant |
| Évaluation acquis (QCM) | Session (questions) + Participant (scores) | Participant |
| Assiduité | Participant | Participant |
| Questionnaire satisfaction | Session (form) + Participant (réponses) | Participant |
| Grille d'observation formateur | Session | Session-only |
| Analyse besoin | Participant | Participant |
| Positionnement | Participant | Participant |
| Checklist formation | Session | Session-only |

- **D-12** : Émargement multi-jours : pattern existant `Attendance` model conservé (2 cases/jour matin + AM, stagiaire + formateur, peu importe N jours). Matrice affiche **1 cellule agrégée** « Émargement » par participant. Click cellule → drawer détail jour × demi-journée.

### Re-génération et actions

- **D-02** : Re-génération ciblée. Deux UX cohabitent :
  - **Bouton ligne** sur action `⋮` de chaque cellule participant-wide → enqueue 1 job BullMQ ciblé `closure-job` mode `single-participant`
  - **Sélection multi** : checkboxes sur lignes → bouton « Re-générer X docs sélectionnés » → batch job
- **D-14** (critère acceptation) : génération/recherche doc en **1-2 clics max** depuis la matrice. Pas de wizard, pas de confirmation chiante.
  - Click cellule doc avec PDF → **ouvre le PDF directement** (nouvel onglet)
  - Click ligne participant → **vue zoom** « tous les docs de Justine pour cette session » (drill 1 niveau)
  - Action `⋮` cellule : Générer / Re-générer / Upload signé / Télécharger / Supprimer (5 actions max)

### UX matrice fiche session

- **D-06** : Style visuel QualiOF (PrioCard + cards + palette Phase 6), pas grille Excel-like Airtable. La matrice est une **card visuelle** avec pastilles colorées :
  - Pastille verte : `MANUAL_OK` (preuve uploadée) OU `GENERATED` validé
  - Pastille orange : coché signé sans upload (warning)
  - Pastille rouge : `MISSING`
  - Pastille grise : N/A (doc session-only n'apparaît pas dans la matrice, voir D-09bis)
- **Docs session-only** (Déroulé / Grille obs / Checklist) : **bloc séparé au-dessus** de la matrice (section « Documents session » avec 3 cards horizontales). Puis section « Documents participants » avec la matrice.
- **Tri matrice** : **configurable + sauvé par user** (en localStorage, par session). Tri par défaut : alpha sur nom participant.
- **Filtres** : statut OPCO, financement, dossier complet/incomplet. Bouton « Voir seulement incomplets ».

### Fiche apprenant

- **D-08** : **Timeline verticale** des sessions. Années comme jalons (2026, 2025, 2024…), sessions comme points cliquables sur la ligne, chaque point ouvre la fiche session correspondante.
- **D-09** : Top de la fiche = **3 PrioCard + 1 bandeau alerte** :
  - PrioCard 1 : Heures totales réalisées (toutes années)
  - PrioCard 2 : Nombre de sessions
  - PrioCard 3 : Heures cette année (vue Airtable « Heures formation 2026 »)
  - Bandeau alerte rouge si : X docs Qualiopi manquants OU paiement en attente

### Fiche produit (TrainingProduct)

- **D-10** : Refonte en **4 onglets** :
  - **Stats** : 4 PrioCard (Sessions réalisées / Apprenants formés total / Heures totales / CA cumulé)
  - **Sessions** : liste sessions de ce produit (clic = drill fiche session)
  - **Apprenants formés** : liste agrégée des stagiaires ayant suivi ce produit au moins 1 fois (drill = fiche apprenant)
  - **Programme** : affichage du programme de formation lié au produit

### Linking + Navigation

- **D-05** : **Cross-navigation Airtable-style systématique**. Depuis n'importe où, tout entité référencée est cliquable :
  - Fiche apprenant → click session → fiche session
  - Fiche session → click participant → fiche apprenant
  - Fiche session → click produit → fiche produit
  - Fiche produit → onglet Apprenants formés → fiche apprenant
  - Doc en matrice → ouverture PDF directe ou drawer

### RBAC

- **D-11** : Matrice fiche session :
  - **ADMIN + MANAGER** : write (générer, re-générer, upload signé, supprimer)
  - **FORMATEUR + COMMERCIAL + COMPTABLE** : read-only
- Application via `requireRole(['ADMIN', 'MANAGER'])` Phase 8 sur toutes les server actions (`regenerateDoc`, `uploadSignedDoc`, `markDocStatus`, etc.)

### Hors scope (à différer)

- **D-13** : Notifications proactives (alerte 7j avant fin de session si docs incomplets) = **Phase 10**, pas Phase 9.1.
- Audit blanc / score 32 indicateurs Qualiopi = **Phase 10**.
- Refonte du module Factures = **Phase 11**.

### Claude's Discretion

- Largeur/styling exact de la matrice (sticky header colonnes, sticky col nom participant, etc.) → cf. patterns Phase 3 responsive et Phase 6 a11y
- Format du drawer émargement multi-jours (modale vs slide-over) → choisir le pattern Radix le plus cohérent avec `ReassignLeadButton` Phase 9
- Choix du store localStorage pour tri/filtres matrice → utiliser un helper `useLocalStorageState` standard
- Animation transitions onglets fiche produit → fade ou slide, à voir

## Specific Ideas

- **Critère acceptation principal D-14** : *« L'auditeur Qualiopi doit retrouver les docs de chaque apprenant en 1-2 clics depuis la fiche session. Et moi (Laurent) je dois pouvoir générer/trouver un doc en 1-2 clics. »* — c'est le test ultime de l'UX.
- **Référence visuelle modèle mental** : la table `Inscriptions` Airtable Refonte (Base `appVyeoX440fAohv2`). À regarder pour comprendre le mental model relationnel, **pas** pour copier le rendu (D-06).
- **Bug P0 résolu structurellement** : Programme = 1 PDF stocké session-wide (`Document.entityType="session"`), affiché N fois dans la matrice avec **statut par-participant** (`SessionParticipant.docStatus`). Plus de duplication PDF, plus de confusion UI.
- **Cohérence existant** : closure-pack en mode batch session continue à fonctionner sans rupture. Le mode `single-participant` est un nouveau path, pas un remplacement.
