## Deviations from Plan

**Total deviations : 1 (Rule 2 — couverture défensive renforcée)** — plan exécuté à la lettre côté `<action>`, avec 1 ajout d'invariant tenant pour resserrer la sécurité multi-tenant.

### Rule 2 — Cross-tenant safety renforcée dans `listProductLearners`

- **Found during:** Task 1 (audit du `<action>` PLAN.md L237)
- **Issue:** Le `<action>` du plan listait `prisma.person.findMany({ where: { id: { in: ... } } })` sans `tenantId`. En théorie un personId issu du groupBy `SessionParticipant` est déjà tenant-scopé (via `session.tenantId`), mais en defense-in-depth (cohérent avec convention Phase 9 D-12 + `buildAuditWhere` Phase 8), j'ai ajouté `tenantId: tenantId` au `where` de `person.findMany`.
- **Fix:** `prisma.person.findMany({ where: { id: { in: ... }, tenantId } })`. Si un personId orphelin (autre tenant) glissait dans le groupBy par erreur, il serait silencieusement exclu plutôt que rendu en UI.
- **Files modified:** `apps/web/src/lib/product-stats.ts:155`
- **Commit:** `fe43126` (Task 1)
- **Tests:** Test 12 (`Cross-tenant : person introuvable → exclu du résultat`) couvre exactement ce cas.

### Note ProductTabs `as any` cast Link href

- **Found during:** Task 2 (typedRoutes Next 14)
- **Pas une déviation** — c'est le pattern repo établi (cf. `learner-tabs.tsx:38`). Le `next.config.mjs` active `typedRoutes: true`, ce qui restreint `Link href` aux routes connues à compile-time. Les hrefs dynamiques (`${pathname}?tab=X`) doivent être castés `as any`. Comportement attendu, documenté dans NAV-03.
