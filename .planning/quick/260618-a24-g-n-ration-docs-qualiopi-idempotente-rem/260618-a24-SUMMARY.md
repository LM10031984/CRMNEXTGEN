# Quick 260618-a24 : Génération docs Qualiopi idempotente Summary

Régénérer un pack ou un document Qualiopi ne crée plus de doublons dans la table `Document` : le worker (ATTESTATION_FIN / CERTIFICAT_REALISATION) supprime puis recrée atomiquement via `prisma.$transaction([deleteMany, create])`, et les 4 generators (convention/convocation/AGEFICE/assiduité) suppriment toujours l'ancien doc du même type avant de recréer — la suppression ne dépend plus du flag `force`.

## Contexte

Mesuré avant correction : jusqu'à 23 CONVENTION et 5 ATTESTATION_FIN pour un même apprenant/session. Deux causes :
1. `worker.ts` créait ATTESTATION_FIN/CERTIFICAT_REALISATION via `document.create()` sans suppression préalable.
2. Les 4 generators avaient déjà un `deleteMany`, mais gardé derrière `if (options?.force)` → empilement en mode par défaut.

Exécuté DIRECTEMENT sur la branche `cloud-migration` (HEAD c874e85). Un run précédent avait par erreur travaillé sur `origin/main` (worker BullMQ-only divergent) ; ses commits ont été jetés. Les fichiers de `cloud-migration` correspondent exactement au plan (worker hybride BullMQ + Postgres FOR UPDATE SKIP LOCKED ; le bloc Document à ~ligne 218).

## Tâches réalisées

### Task 1 — worker.ts idempotent (commit c9c6312)
- Bloc `if (docType) { document.create(...) }` remplacé par `const [, doc] = await prisma.$transaction([ document.deleteMany({ where: { tenantId, sessionId, participantId, type: docType } }), document.create({...}) ])`.
- where du deleteMany : `tenantId + sessionId + participantId + type` → 1 seul Document par triplet.
- PedagogicalAsset `upsert` juste en dessous : **non touché** (déjà correct).
- Test `worker-idempotent-document.test.ts` (3 tests) : ATTESTATION → ATTESTATION_FIN, CERTIFICAT → CERTIFICAT_REALISATION (deleteMany+create dans le même $transaction), QCM → ni deleteMany ni create sur Document (branche docType skippée, PedagogicalAsset.upsert appelé).

### Task 2 — 4 generators deleteMany inconditionnelle (commit 76455a7)
- `convention-generator.ts`, `convocation-generator.ts`, `agefice-generator.ts`, `agefice-attendance-generator.ts` : retrait du wrapper `if (options?.force) { ... }` autour du `deleteMany`, appel rendu inconditionnel.
- `where` des deleteMany **inchangés** (tenantId + type + participantId) ; types : CONVENTION / CONVOCATION / AGEFICE / ASSIDUITE.
- Signature `options?: { force?: boolean }` **conservée** sur les 4 fonctions (compat appelants). `noUnusedParameters` non activé → pas d'erreur tsc sur le param désormais non lu.
- Blocs d'idempotence par hash sha256 (`findFirst { hashSha256 }`) et PedagogicalAsset : **non touchés** (le deleteMany inconditionnel s'exécute avant).
- Test `generators-idempotent.test.ts` (4 tests) : chaque generator appelé SANS `options` invoque `deleteMany` exactement une fois avec le bon `where`/type. `findFirst → null` court-circuite après la suppression (preuve que delete a eu lieu sans force).
